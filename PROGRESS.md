A hand edit to the file is overwritten on the next change (the file says so in a comment); tests parse the file back and compare it to the table.
- M10 fix capture: a reject cannot know the fix yet, so the next `complete_task` summary becomes `fix_applied` on that task's newest lesson that has none (never overwrites a recorded fix). `reject_task` also accepts optional `prevention` and `fix_applied`; audit FAILs pass a prevention built from the unmet criteria, failed checks and findings.

- M11 `task-update` maps the target status to the one trigger core allows from the current status (todo->in_progress = start, blocked->in_progress = unblock, review->in_progress = reject, in_progress->review = complete, review->done = approve, todo/in_progress->done and todo->review use `skipSteps`). Same status is a 200 no-op. Actor = `completed_by` if given, else the `webhook` agent; unknown ids are auto-registered as `external`. Approval goes through core's independence rule, so a webhook that submitted a task cannot approve it (409): send `completed_by` with a different id (e.g. `github`) for the final step. `completed_at` is accepted and ignored.
