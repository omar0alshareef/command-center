# M14 handoff: Orchestrator and multi-provider runners (Slice 1 + the rest)

Slice 1 was committed first as `c115ae8 feat(M14a)`. The rest is `feat(M14)` (this commit). The operator's standing authorisation covers the rest of M14 without waiting; there is one handoff for both.

**Built**
- **Data (migration 007, then 008):**
  - `agents.model` (007).
  - `agents.provider` and `agents.max_concurrent`.
  - `subtasks.provider_override`.
  - `runs`: status, provider, model, kind work/review, attempt, tokens, `est_cost_usd` with `cost_basis` reported/estimate, error, output tail, `cancel_requested`.
  - Typed core queries.
  - Deleting a task deletes its runs.
- **Providers (`packages/core/src/providers/`):** one interface with timeout, `AbortSignal` cancel and an output cap.
  - `claude-code`: `claude -p --output-format json` in the project folder, prompt on stdin, exact tokens and cost, process tree killed on cancel.
  - `anthropic-api`, `openai-api`.
  - `gemini`: CLI when installed, else API.
  - `local`: Ollama or LM Studio, models from the server.
  - Keys go only in request headers and are redacted from every error.
  - Approximate price table for estimates.
  - `killTree` moved into core and is shared with the terminal and planner.
- **Orchestrator (`packages/core/src/orchestrator.ts`):**
  - `readyTasks()` is pure and ordered by milestone start, priority, due date, id.
  - A 5-second tick plus a kick on database changes.
  - Limits: global concurrency, per-agent concurrency, hourly cap, daily spend ceiling, per-run timeout.
  - Run flow: start, provider call, `complete_task` with the agent's `SUMMARY:` line.
  - A failed run is retried once, then the task is blocked with the error.
  - A cancel kills the process tree and blocks the task.
  - Pause (finish or cancel in-flight runs), stop after current, manual "Run with agent" on the same path.
  - Recovery of stale runs, and a shutdown on quit that writes the last rows.
  - The reviewer rule and an opt-in automatic review by a different agent.
- **App wiring:**
  - `orchestrator-loop.ts`, `orchestrator-api.ts` and `provider-settings.ts` (keys encrypted with `safeStorage`).
  - Typed IPC; the renderer never sees a key.
  - Orchestrator status pushed to the renderer.
  - A graceful shutdown before the database closes.
- **UI:**
  - Agent Hub: an Orchestrator card (Start / Pause / Stop after current / Resume, with the finish-or-cancel dialog), plus Provider and Model dropdowns per agent. Providers that are not detected are disabled.
  - Settings → Providers: detection, keys, base URLs, Test connection, editable model lists, the limits and the auto-review switch.
  - Task modal: a provider override, "Run with agent", and Cancel run.
  - A run dialog (output tail, tokens, cost labelled estimate) opened from the feed's Output button or the task's History runs list.
  - The status bar shows state, running, queued and spend against the ceiling, and "Paused by cap".
- **MCP and CLI:**
  - `list_runs` and `cancel_run`, 30 tools. There is no approve-run tool.
  - `command-center orchestrate --status|--pause|--resume` and `command-center runs --task`.
  - `list_agents` also returns provider, model and executor.

**Bugs the live runs found (fixed):**
- Every agent row had its own `db:changed` listener, which gave `MaxListenersExceededWarning` once a project had more than ten agents. The model lists are now one shared store with one listener.
- The second attempt of a run left a stale in-flight entry. Tracking is now one entry per task with a moving run id.
- A run's model was recorded as "default" for API providers. It now records the model actually called.
- The test scripts' first runs also caught a locked Chromium file in my key scan (now skipped and counted) and an edit that had not applied.

**Deviations / ambiguities:** see the "M14" bullets in PROGRESS.md.
