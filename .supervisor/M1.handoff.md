## Deviations / ambiguities (also in PROGRESS.md)
- `schema_version` is created by the runner, not migration 002 (must exist before migrations run). Migrations are TS string modules, not `.sql` files.
- Migration 002 also inserts built-in agents `operator` and `system` so `agent_log` FKs resolve. `transition()` defaults `actor` to `operator`; other actors must already be registered (M4 auto-registers).
- Skip-step moves (todo→done, todo→review) are NOT legal in the core yet; M3 adds a confirmed skip path.
- `start` throws `DependenciesIncompleteError` for unfinished `depends_on` unless `force: true` (my addition, for the board's "start anyway?").
- JSON shapes chosen: `acceptance_criteria` = `{text, done}[]`, milestone `notes` = `{text, author, at}[]`.
- `lessons_learned.fix_applied` is `''` on reject; M10 fills it.
- Activity feed pages by `(timestamp, id)` cursor, not offset.
- Versions pinned: better-sqlite3 13.0.3 (blueprint said ^11; latest stable used per D12), zod 4.6.5, tsx 4.23.15.
- Commit author is a repo-local identity (`umar.alshareef1999`), since no git identity existed.
- `CLAUDE.md` (Supervisor handoff section) and `scripts/await-approval.mjs` were added by someone else mid-M1; I did not edit them. They are committed in the handoff commit now that the user confirmed this workflow.
