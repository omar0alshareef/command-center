## Findings you should know about
1. **The real `claude` CLI is not usable here**: it prints "Not logged in" (run outside a terminal it exits in ~4 s with that message). So the `claude` runner is verified against a stand-in binary that speaks the same interface, plus the real flag set from `claude --help` (`-p`, `--tools`, `--allowedTools`, `--permission-mode`, `--append-system-prompt-file` all exist; I confirmed `--append-system-prompt-file` is accepted and a missing file errors). A real end-to-end run needs your login.
2. **`claude -p` hangs when started from a process that runs inside a ConPTY** (any shell in the app's Terminal), on this machine, even with a pipe for stdin and `windowsHide`/`detached`; the same call from a plain shell exits in 4 s. I could not tell whether that is this machine's Claude config or a general ConPTY interaction. So in the app's terminal `--runner auto` (which prefers `claude`) can sit until `--timeout` (default 15 min). Mitigations in place: `--timeout`, `--runner local`, and a clear `[1/3]` progress line. This needs your eyes once you are logged in.
3. The M8 test started the real `claude` interactively once (first-run screen, may have written config); nothing in M9's tests starts the real `claude` at all except `claude --help` and the not-logged-in probes above.

## Deviations / decisions (PROGRESS.md)
- Default runner is `auto` (claude if found, else local with a printed note); the local runner is deliberately honest: it writes no code, so `start` with it never completes a task.
- Audit checks and the secret scan are deterministic CLI work; the model reasons over their output and cannot override a deterministic FAIL (a missing verdict is FAIL; a runner error aborts without touching the task).
- `complete_task` after `start` is attributed to the task's assignee when it is a registered non-human agent, else `operator-cli` (approval stays with the human; independent-review rule untouched).
- `--check` commands run through the shell on purpose (they are the operator's own flags or the project's scripts, never agent text).
- The CLI's `ELECTRON_RUN_AS_NODE` is removed on startup so child processes (`claude`, `npm`) do not inherit it.
