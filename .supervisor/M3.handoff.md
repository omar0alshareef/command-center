- Polish: `color-scheme` per theme so scrollbars/checkboxes follow the theme.

## Deviations / ambiguities (also in PROGRESS.md)
- Block / Reject / summary prompts are small modal dialogs, not popovers anchored to the card.
- No "updated by claude-code" notice in the modal; instead focused field drafts are never overwritten by outside changes, and refetches are held during drags and mutations.
- Blocked tasks can only return to their previous column; done tasks can't be dragged (Reset in the modal); dragging back to To Do is illegal (Reset). These follow the §6.2 table where it is explicit and are my reading where it is silent.
- Schema change: migration 003 (`started_at`, index). Blueprint Phase 1 schema is otherwise unchanged.
- `window.__ccRenders` test hook in `TaskCard` (inert unless set).
- Prepare button and "Open in terminal" are disabled placeholders (M9 / M8). Dependencies are edited as a plain list.
- Renderer bundle 1.26 MB; verified it contains no `better-sqlite3` or `zod`.

## Could not verify / known issues
- Pointer drags use CDP mouse events, not a hand; real hardware (touch, high-DPI, trackpad inertia) untested. Windows 11 only.
- Framer layout spring between columns was never seen in motion (static screenshots only) — **this and general look-and-feel need the user's eyes** (your SUPERVISOR.md asks for that after M3).
- dnd-kit intentionally swallows clicks for ~50–100 ms after a drop; a scripted click inside that window is lost. My script waits 400 ms like a person; I did not change app behavior for this.
- One unexplained failure, same family as M2's Rollup crash: in a run made while the modal-focus regression was present, the very first drag (B) timed out before reaching the DB. It did not recur in the 7 full runs on the final code. Cause not identified; I never reproduced it in isolation.
- Bugs found by this evidence and fixed before commit: React error #185 (Zustand selector returned a new `Map`), the dnd-kit context/memo issue above, a `tabIndex` wrapper that stole the reason textarea's initial focus, same-millisecond log ordering.
- Filter bar's Assignee multi-select and the context bar's prev/next buttons were not clicked live (logic is unit-tested; Priority multi-select and `]` were).
- Security posture unchanged from M2 (contextIsolation on, no `require`/`process` in the renderer, no SQL channels) plus zod-validated task IPC with a fixed actor; I did not do a dedicated security review of the new IPC.
