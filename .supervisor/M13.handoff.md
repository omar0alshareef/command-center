# M13 handoff: Planning Workspace

**Built**
- **Data (migration 005):** `subtasks.due_date`, `planning_sessions` (idea, status, `requirements` Q&A, `last_error`), `planning_documents` (manifesto/roadmap, versioned, draft/approved/superseded) and `planning_proposals` (one staged JSON per session). The roadmap called this "003"; 003 and 004 were taken.
- **Core `planning.ts`:** session/document/proposal store, zod schemas for every stage output (D20), `parseStageOutput` (one JSON object, field-named errors), `proposeTeam` (capability → role, D21), `findCycle` and `validatePlan` (missing milestone, missing dependency, cycles, unknown assignee, reserved ids), `approvePlan` (one transaction plus a `fault` test hook), `plannerPrompt` per stage. `due_date` is an editable task field (real-date validated).
- **Main process:** `planner.ts` with stages interview → draft_manifesto → draft_roadmap → plan_capabilities → plan_tasks → propose_team (deterministic). Two runners behind one interface: `claude -p` child process (stdin prompt, timeout, 200K cap with notice) and the Anthropic API key (D18/D19). Output streams to the panel. Cancel kills the process tree. `planning-api.ts` is the validated IPC. The API key is encrypted with `safeStorage` and only "set (…1234)" reaches the renderer. `kill-tree.ts` is shared with the PTY manager.
- **Renderer:**
  - Planning tab (`Ctrl+6`): session list, interview chat (answers autosave, `Ctrl+Enter` sends), live planner output with Cancel, an error block naming the failing field, and draft tabs.
    - Manifesto and Roadmap: markdown render plus edit.
    - Milestones: dates, capabilities and the roles each needs.
    - Tasks: milestone, priority, due date, assignee, depends on.
    - Team: rename, remove or add roles.
  - Planner assumptions are highlighted, and a "Fix before approving" list sits under the drafts.
  - Approve dialog lists the counts.
  - Due date in the task modal, and a past-due flag on cards and in the modal.
  - The milestone panel shows the milestone's approved roadmap entry.
  - Settings → Planner: runner, model, key, and viewers for the approved manifesto and roadmap.
  - "Plan a project" button on the empty-board state.
- **MCP:** `get_planning_documents` and `get_planning_session` (read-only). No approve tool, so the server now has 28 tools (README updated).
