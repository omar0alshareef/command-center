## What I built
**Core (`packages/core`)**
- Migration **004**: `lessons_learned.prevention`, and the FTS5 index rebuilt over reason + fix + prevention (FTS5 columns cannot be altered; old rows are preserved and re-indexed, tested against a database that only had migrations 1–3).
- `lessons.ts`: `addLesson` (+ prevention), `updateLesson`, `deleteLesson`, `recordFixForTask`, retrieval (`getRelevantLessons`, `getLessonsForTask`, stop-word filter, own rejections first), `lessonLine`, and the markdown side: `renderLessonsMd`, `syncLessonsFile`, `parseLessonsMd`, `lessonsFilePath`.
- `state-machine.ts`: `reject` accepts `prevention` / `fixApplied`; `complete` records the summary as the fix of the task's newest unresolved lesson; the file is rewritten **after** the transaction commits and a write failure never fails the transition. `context.ts` uses the task's own lessons + related ones (label and acceptance-criteria words).
**MCP:** `reject_task` takes optional `prevention` and `fix_applied`; `complete_task` documents that its summary becomes the fix; `enrich_task` now also returns `relevant_lessons`; `get_lessons_learned` and the history result include `prevention`.
**CLI:** `command-center lessons [--task|--query|--limit|--json]`; `prepare` syncs the file and feeds lessons (with prevention) to the optimizer; `audit` FAIL stores a prevention built from the unmet criteria / failed checks / secret findings.
**App:** IPC `lessons.update` / `lessons.remove` (zod-validated, through core); Agent Hub **Lessons** card (count, search, edit, delete with confirm); History rejection cards show Prevention. README gets a "Lessons learned" section.

## Deviations / decisions (PROGRESS.md)
- The table is the source of truth; the markdown is a generated view rewritten on every change (a hand edit is overwritten, and the file says so). This is what makes "stay in sync" true by construction rather than by merging.
- The roadmap says "a Lessons list in Settings **or** Agent Hub": I used the Agent Hub (Settings arrives in M12).
- Lessons list sits in the Agent Hub's right column above Performance; on a 1200×800 window you scroll to it.
- Retrieval uses a small stop-word list (`add`, `the`, `new`, …) so filler words never match; this changes ranking for existing databases slightly.
- The fix capture is a heuristic by design: the first completion summary after a rejection is "the fix". Edit it in the Lessons list if it is wrong.
