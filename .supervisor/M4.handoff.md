## What I built
**`packages/mcp-server`** (stdio, `@modelcontextprotocol/sdk` 1.32.1, zod 4)
- `src/server.ts` `createServer({db, env, now})`: 25 tools + server `instructions` describing the loop. Transport-agnostic (tests use an in-memory pair; `index.ts` uses stdio).
- `src/tools/{read,task,milestone,agent}.ts`: 9 read, 10 task write, 5 milestone write, 1 agent. **No SQL here: every write is a core function** (`transition`, `updateTask`, `enrichTask`, `createTask`, `registerAgent`, `addMilestoneNote`, `setMilestoneDates`, `updateDrift`, `createMilestone`, `logAction`).
- `src/session.ts`: caller identity. `src/results.ts`: `guard()` + `describeError()` (every throw becomes an `isError` result naming the next tool). `src/tools/shared.ts`: `tool()` registers with a **strict** schema.
- `src/index.ts`: needs `PROJECT_ROOT` **and an existing `command-center.db`** (never creates a board); stdout carries only protocol messages, logs go to stderr; uncaught errors are logged, not fatal.
- `build.mjs`: esbuild → `dist/index.js` (1.6 MB), only `better-sqlite3` external. `npm install -g --prefix <tmp> ./packages/mcp-server` creates a working `command-center-mcp` bin (tested).

**Core additions** (`packages/core`): `agents.ts` (`registerAgent` upsert, reserved ids, parent/cycle checks, `isAgentActive`), `milestones.ts`, `enrichTask`, `createTask` extra fields in one transaction, assignee must be a registered agent, `overview.ts` (`getProjectStatus`, `getMilestoneOverview`, `getTaskSummary`), `tokens.ts` (`capTokens`), `getLessonsForTask`.

**App**: `McpConnect` card in the Agent Hub (empty state when no agents, else a "Connect another agent" disclosure) showing the real `claude mcp add` command and config block; `main/mcp-path.ts` resolves the bundle path; `lib/mcp-config.ts` builds the strings (unit-tested).

**Fixes found by the live checks** (all in `apps/desktop`): Esc on a confirm stacked over the task modal closed **both** (React bubbles the synthetic `onCancel`; fixed in `Modal`); board columns now fit at 1200×800 (min 216 px); stray horizontal scrollbars in columns; blue focus ring on the task modal (global `:focus-visible` moved into `@layer base`); Agent Hub no longer stacks two big empty states.

## Your M3 cautions for M4
- **All 25 tools go through core `transition()`/core writers.** Yes; the server package has no `prepare`/`exec`.
- **Actor must be registered; never spoof `operator`.** The caller is the *session agent*: derived from `clientInfo.name` (or `COMMAND_CENTER_AGENT_*`), auto-registered on first write. Optional `agent_id` is accepted only for a registered non-human agent; `operator`, `system` and human agents are rejected on every write tool (tested on start_task, log_action, update_task, create_milestone, add_milestone_note × operator/system/human; DB log count unchanged). A client *named* "operator" becomes `operator-agent`; one colliding with a human agent gets `<id>-agent`. `register_agent` offers only orchestrator/sub-agent/external. Live L7: `approve_task {agent_id:"operator"}` → refused, card did not move.
- **Size caps with truncation notice.** `get_task_context` ≤ 8,000 tokens (tested with a 100K-char task: result ≤ 8,000 with `[truncated: ~N of ~M tokens omitted … Call get_task_summary …]`); `get_task_summary` ≤ 500 tokens for all 60 seeded tasks and for a pathological one (shrunk field by field, still valid JSON).
- **Errors actionable, never crash.** See above. Unknown keys are rejected (SDK's default silently strips them, which made `update_task({status:"done"})` look successful; all schemas are now strict).
- **zod schemas with clear descriptions.** Test fails if any tool description < 40 chars or any parameter lacks a description (it caught undocumented date and task-field parameters; fixed).
- **Show a tool call moves a card live in the built app.** Live L3/L5/L11/L12 plus screenshots I viewed (card in To Do → In Progress → amber Review).

## Decisions to confirm (my policy calls)
- `update_drift` recomputes `project.schedule_status` from the worst milestone drift (≥7 days behind → `behind`, ≥1 → `at_risk`, else `on_track`) so the title-bar pill follows agents. This **overwrites** a manually set status. Say if you'd rather it not.
- `approve_task` / `reject_task` are exposed to agents (the blueprint lists them). The server instructions say not to approve your own work, but nothing enforces it. Should approval be operator-only?
- Claude Code sets `CLAUDE_PROJECT_DIR` for stdio servers (per its docs); I did **not** use it as a `PROJECT_ROOT` fallback (the config sets `PROJECT_ROOT` explicitly, and guessing wrong would target the wrong board).
- Tool definitions total ~27 KB (≈6.8K tokens) of agent context for all 25. They declare JSON Schema draft-07 with valid property names (Claude Code skips its draft-2020-12 check for other dialects and requires names `[A-Za-z0-9_.-]{1,64}`: all pass).
